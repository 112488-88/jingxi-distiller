> 目的：不是学花活，是搞清楚「为什么有些界面看着就专业」。
> 来源：GitHub 上的具体实现与设计规范，逐条落到鲸汐提炼器。

## 二、提炼出的六条规律

### 1. 动效的「时长 + 缓动」有公认区间

- 微交互（hover、press、tag 出现）：**100–150ms**，`cubic-bezier(.2,.6,.3,1)` 这类快出慢收
- 面板/抽屉：**200–300ms**；入场用 `ease-out`，出场用 `ease-in`（出场比入场略快）
- 位移量：**4–12px** 就够。位移 30px 以上会「飘」
- 抽屉/弹层用 **弹簧**（spring）比贝塞尔更像物理：`stiffness 300 / damping 30` 一类，但只在「被拖拽」的交互里值得，纯点开的用贝塞尔更省事

> 我现在的数：hover 130ms、卡片入场 260ms、抽屉 260ms、toast 3000ms。前三个在区间内，抽屉偏上沿，可以缩到 220ms。

### 2. Toast 的默认值是被大量项目验证过的

Sonner 的默认值（我从它 API 文档里抠的）：`duration 4000ms`、同屏 `visibleToasts 3`、`position bottom-right`、`offset 32px`（移动端 16px）、`gap 14`、hover 展开、可滑动关闭、`⌥T` 聚焦。

我原来：2400ms、不限条数、点了不能关。→ **已按它的思路改**：3000ms、同屏最多 3 条、点一下关掉。

### 3. 「滚动包含」是专业度的分水岭（这条最容易漏）

edgequake 那份 SPEC 里第一位的 bug 就是：**在下拉列表里滚鼠标，列表滚到底后整页跟着滚**。修法一行：

```css
.列表容器 { overscroll-behavior: contain; }
```

同理还要 `stopPropagation`（如果是嵌套在可滚容器里）。我原来 5 个内部滚动区（历史列表、附件预览、抽屉正文、诊断框、toast 区）**全都没加**。→ 已补。

### 4. 加载时不要卸载列表（状态连续性）

cmdk 那份 SPEC 明确写：fetch 期间如果把列表 unmount 掉，↑↓ 就失效、用户失去位置感。正确做法是**保留旧内容 + 叠一层 loading**，而不是清空重画。

映射到我的工具：现在点「一键提炼」会先把旧卡片删掉换成骨架屏 —— 用户如果想对照上一条结果就不行了。**待改**：旧卡片保留并压暗 40%，骨架叠在上面。

### 5. 键盘可达性不是加分项，是基准

那份 SPEC 的交互契约列得很清楚，可直接抄：

| 输入 | 应该发生什么 |
|---|---|
| 打开面板 | 焦点落到搜索/输入框 |
| ↑ ↓ | 移动高亮，**到两端要循环** |
| Enter | 选中并关闭 |
| Esc | 关闭，**焦点还给触发按钮** |
| Tab | 在面板内循环，不逃逸 |
| 列表滚动 | 只滚列表，不滚页面 |

我的抽屉：Esc 关了（✓）但**焦点没还给把手**；打开时焦点也没进抽屉；没有 Tab 循环。这是真缺口。

### 6. 「专业感」八成来自留白、层级和数字对齐，不是特效

- 三级 surface（页面底 / 卡片 / 内嵌块）+ 四级 ink（主文字/次文字/说明/占位）—— Lobe 那套，我已经在用
- 数字一律 `font-variant-numeric: tabular-nums`，否则「0.0 秒」和「4.8 秒」宽度不齐，扫读时晃眼 —— 已用
- 描边比阴影更能表达层级：卡片用 `1px border + 极轻阴影`，浮层才用大阴影 —— 已用
- 大量项目栽在「所有东西都加阴影」和「所有字号都 14px」

## 三、自查：鲸汐提炼器现在的水平

| 规律 | 现状 | 结论 |
|---|---|---|
| 动效时长/缓动 | 130 / 260 / 260ms | 基本合规范，抽屉可缩到 220ms |
| Toast 规范 | 原来 2400ms、无上限、不可关 | **已修**：3000ms / 最多 3 条 / 点击关闭 |
| 滚动包含 | 5 个滚动区都没加 | **已修**：统一 `overscroll-behavior: contain` |
| 加载不卸载 | 会清掉旧卡片 | ❌ 待改（保留旧卡片 + 压暗 + 骨架叠加） |
| 焦点管理 | Esc 能关，但焦点不回把手 | ❌ 待改（开→聚焦抽屉标题；关→还给把手） |
| Tab 循环 | 无 | ❌ 待改（抽屉内 `inert` 主区 或 手写 focus loop） |
| 触摸目标 | 勾选圈 18px、抽屉把手 18px | ⚠️ 低于 44px 建议值（桌面可接受，触屏偏小） |
| 动效克减 | `prefers-reduced-motion` 全局生效 | ✅ |
| 数字对齐 | `tabular-nums` | ✅ |
| 色彩不单靠色相 | 四种标记用线型 + 字形 + 形状 | ✅（比大多数项目做得细） |

## 四、下一步清单（按性价比排序）

1. **加载保留旧卡片**（感受最明显）：`showSkeleton` 改成不清空 `.card`，给旧卡片加 `.is-stale { opacity:.45; filter:saturate(.6) }`，骨架绝对定位盖在上面
2. **抽屉焦点管理**：打开 `refBody` 前先 `refHide.focus()`；关闭后 `refHandle.focus()`；抽屉加 `role="dialog" aria-modal="false" aria-label="原文对照"`
3. **键盘循环**：给抽屉的「全文/大纲」和 `.toc-chip` 加 ← → 支持（可选，收益中）
4. **触摸目标**：把勾选圈从 18px 扩到 22px（视觉不变，用 `::before` 扩点击区到 40px）
5. **抽屉时长** 260 → 220ms，出场 180ms

## 五、不值得做的（避免过度设计）

- 骨架屏的「呼吸光」再花哨也没用，第一次 1 秒就消失
- 卡片入场用弹性回弹（overshoot）在信息型界面里显廉价
- 逐条 stagger 延迟（每条 +40ms）超过 6 条就会让人等
- 视差、粒子、3D 翻转 —— 这个工具的用户是来读内容的，不是来看效果的
